# Handoff: TurnMate — 강사 근무·대직·급여 앱 리디자인 + GPS 출근 반경 알림

## Overview

`턴메이트(TurnMate)`는 수영장 강사가 **대직(대체 강사) 요청·지원, 정규 근무표 확인, 급여 명세 확인, 출퇴근 기록**을 한 앱에서 처리하는 서비스입니다. 이 번들은 원본 코드(`reference/turnmate-main`, React + Firebase)의 기능을 전부 세어 정리한 뒤, 그 위에서 화면을 다시 설계한 결과입니다.

이 앱의 중심 문제의식은 하나입니다.

> **강사는 수영장에서 젖은 손으로 앱을 쓴다.** 폼을 채우게 만들면 안 쓰게 된다.

그래서 리디자인의 원칙은 세 가지입니다.

1. **입력 마찰 제거** — 강사가 직접 입력하는 항목을 최소화하고, 나머지는 시스템·관리자가 채운다.
2. **터치 타깃 하한 상향** — 원본의 10~11px 텍스트 200여 곳, 9px 배지, 36px 버튼을 본문 14.5~16px / 주요 버튼 52px로 올렸다.
3. **색은 의미만** — 중립 잉크 + 정규(파랑) · 대직(주황) · 긴급(빨강) · 완료(초록). 그라데이션·이모지·8색 배지는 제거.

## About the Design Files

이 번들의 HTML/JSX 파일은 **디자인 레퍼런스**입니다. 실제 동작하는 고충실도 프로토타입이지만, 프로덕션 코드가 아닙니다. 그대로 배포하지 마세요.

해야 할 일은 **이 HTML 디자인을 대상 코드베이스의 기존 환경(React, Vue, SwiftUI, Flutter, 네이티브 등)에서 그 환경의 패턴과 라이브러리로 다시 만드는 것**입니다. 아직 코드베이스가 없다면 프로젝트에 가장 적합한 프레임워크를 선택해 그 위에 구현하세요.

원본 앱은 React + Firebase였으므로 React 계열이 자연스러운 출발점입니다. 다만 **GPS 반경 감지와 백그라운드 알림은 웹으로는 완전히 구현되지 않습니다**(아래 Interactions 섹션의 "웹의 한계" 참고). 이 기능이 제품의 핵심이라면 네이티브 셸(React Native / Capacitor / SwiftUI)을 검토해야 합니다.

## Fidelity

**High-fidelity (hifi).** 최종 색상·타이포그래피·간격·인터랙션이 모두 확정된 상태이며, 프로토타입은 실제로 클릭·입력·계산이 동작합니다. 코드베이스의 기존 라이브러리와 패턴을 쓰되 **픽셀 단위로 동일하게** 재현하세요. 아래 Design Tokens의 값은 CSS에서 그대로 옮겨 쓰면 됩니다.

## ⚠️ 이번 릴리스에서 아직 설계되지 않은 것 — 정규시간표 자동 채움

이 대화에서 합의된 **가장 중요한 구조 변경**은 프로토타입에 **아직 반영되어 있지 않습니다.** 현재 프로토타입의 온보딩 3단계는 강사가 정규 시간표를 **직접 입력**하는 구조입니다(`app/onboarding.jsx`). 이것을 아래 구조로 바꾸는 것이 이번 작업의 실제 목표입니다.

### 결정 사항 (대화에서 확정된 것)

| 항목 | 결정 | 근거 |
|---|---|---|
| 강사가 입력하는 항목 | **이름 · 전화번호 · 근무 지점(드롭다운 1개)** | 지점은 시간표가 아니라 프로필 정보 |
| 정규시간표 | **강사가 등록하지 않음.** 원본 데이터(학원 엑셀)에서 시스템이 미리 채움 | 강사 70명, 원본 엑셀 존재 |
| 시간표 수정 권한 | **강사에게 없음.** 운영 담당자가 엑셀 재업로드로 갱신 | 학기 개편·보강·지점 이동이 잦음 |
| 강사의 유일한 액션 | **`[맞아요]` 1탭 확인** | "자동 등록"이 아니라 "제안 + 확인" |
| 학기 기간 | **전역 설정 1개** (강사별 아님) | 원본 데이터에 유효기간 없음 |
| 지점 좌표 | 관리자가 최초 1회 입력 (지점 10곳 안팎) | 엑셀에 지점 컬럼 없음 |
| 매칭 키 | **정규화한 전화번호**, 이름은 확인용 | 동명이인·개명·재입사 방어 |

### 반드시 지켜야 할 두 가지

1. **이름을 매칭 키로 쓰지 마세요.** 키는 `정규화(전화번호)`(`010-1234-5678` → `01012345678`)이고, 이름이 일치하면 자동 통과, 불일치하면 운영자 확인 큐로 보냅니다. 매칭 실패는 **조용히 0건 처리하지 말고 임포트 결과에 "매칭 실패 N건"으로 노출**하세요.
2. **강사 화면에 시간표 편집 UI를 만들지 마세요.** 편집 UI가 없으면 잘못 입력할 일도 없습니다. 강사에게는 읽기 전용 카드 + `[맞아요] / [달라요]`만 노출합니다. `[달라요]`는 사유 한 줄과 함께 운영자 큐로 들어가고, **강사가 직접 고치지 않습니다.**

### 필요한 화면 (신규, 미설계)

- **프로필 등록 (수정)** — 기존 온보딩 1단계에서 `근무 지점` 드롭다운 1개 추가. 3단계(정규 시간표 직접 입력)는 **삭제**.
- **시간표 확인 카드 (신규)** — 홈 또는 내 정보에 배치.
  ```
  [내 정규 시간표]
   화 15:00–18:00  ○○지점
   목 15:00–18:00  ○○지점

   이 시간표가 맞나요?
   [ 맞아요 ]   [ 달라요 ]
  ```
  `[맞아요]` 탭 시각을 기록하세요. 나중에 "알림이 이상하다"는 민원에 "본인이 3월 2일 확인함"이라고 답할 근거가 됩니다.
- **임포트 결과 화면 (관리자, 신규)** — 파일 선택 → 미리보기 → 반영. 성공/실패 건수와 매칭 실패 큐를 보여줍니다. 70명 규모에는 어드민 CMS가 과하고, 코드 하드코딩은 학기마다 배포를 요구하므로 **"업로드 버튼 하나"가 중간 지점**입니다.
- **학기 설정 (관리자, 기존 설정 탭에 추가)** — `2026 봄학기 2026-03-02 ~ 2026-06-20 [알림 켜짐]`. 학기 밖이면 출근 알림을 자동으로 끕니다(방학 오탐 방지).

### 남는 리스크 (설계로 완전히 없앨 수 없음 — 문서화만)

- **방학·공휴일** — 학기 설정으로 완화. 공휴일은 예외 날짜 목록으로.
- **보강·대타** — 정규시간표에 없는 날은 알림이 안 옵니다. 미탐은 오탐보다 발견이 늦습니다.
- **퇴사·지점 이동** — 엑셀을 갱신하지 않으면 유령 강사에게 알림이 갑니다. **임포트를 반복 가능하게**(같은 파일 다시 업로드) 만들어 자연스럽게 해결하세요.
- **두 지점을 도는 강사** — 슬롯별 지점이 필요합니다. 70명 규모에서는 0~5명일 가능성이 크므로 **1단계는 지점 1개로 시작하고, 실제로 발생하면 그 강사의 슬롯 몇 개에만 지점을 덮어쓰는 예외 테이블**을 추가하세요. 처음부터 슬롯별 지점을 설계하면 1,000건 전부에 지점을 채워야 해 운영 부담이 10배가 됩니다.

## Screens / Views

프로토타입은 **402 × 874** (iPhone 15/16 논리 해상도) 프레임 안에 그려집니다. 모든 화면 좌우 패딩은 **16px**(목록) 또는 **20px**(헤더), 스크롤 영역 상단은 상태바 아래 **54px**입니다.

### 강사 모드 · 탭 4개

#### 1. 온보딩 (4단계)
- **Purpose**: 최초 실행 시 프로필 등록. 완료 전에는 앱 전체가 이 화면입니다.
- **Layout**: 전체 화면, 상단 54px 아래 진행 인디케이터(가운데, 활성 점 22×6px / 비활성 6×6px, 6px 간격), 하단 고정 버튼 영역(`padding: 10px 24px 34px`), 본문 스크롤.
- **Steps**: `기본 정보` → `자격증과 프로그램` → `정규 시간표` → `확인`
  - 1단계: 이름, 연락처, 소속 센터(읽기 전용, 배경 `bg`), 직급 칩 4개(위촉강사/전임강사/주임/팀장), 수영 경력 3개 옵션 카드(각 카드에 해당 단가 표시 → 단가가 선택 근거가 됨)
  - 2단계: 자격증 칩 6개, 프로그램 칩 5개
  - **3단계: 정규 시간표 — 위 "미설계" 섹션에 따라 이 단계는 삭제 대상입니다.**
- **Validation**: 1단계 `이름 2자 이상 && 연락처 9자리 이상`일 때만 `다음` 활성. 연락처는 숫자·하이픈만 허용.
- **Copy**: 제목 `턴메이트에 오신 걸 환영해요` / 리드 `수영강사를 위한 대직·근무·급여 관리. 4단계면 끝나요.`

#### 2. 홈
- **Purpose**: 오늘 몇 시에 어디서 뭘 하는지 → 출근 → 급여 순서로 한 화면에서 해결.
- **Layout**: 세로 스택, `padding: 6px 16px 26px`, gap 12.
- **Order (오늘 근무가 있을 때)**: 인사말 → 다음 근무 카드 → 오늘 남은 근무 → 센터 도착 알림 → 긴급 대직 → 내 대직 → 월 급여 → 액션 카드 2개.
- **Order (오늘 근무가 없을 때)**: 인사말 → **월 급여(맨 위로 이동)** → "오늘은 배정된 근무가 없어요" 카드 + 다음 근무일 행 → 센터 도착 알림 → … 이 재배치는 "오늘 볼 게 없으면 급여와 다음 근무라도 보여준다"는 의도입니다.
- **인사말**: `13.5px/600 ink3` 날짜(`10월 6일 (화)`) + `25px/790 letter-spacing -0.7` 제목. 2줄 고정: `{이름} 강사님,` / `오늘 근무 {n}건이에요`.
- **다음 근무 카드**: `Card` padding 0, 상단 `18px 20px 16px`, 하단 2분할 버튼(54px, 구분선 1px `line2`).
  - 상태 라벨 `13px/720`: 출근 전이면 `blue`, 도착했으면 `green`, 출근 완료면 `green`. 문구는 `다음 근무 · {start} 시작` / `센터에 도착해 있어요` / `출근 완료 · 근무 중` / `오늘 근무 완료`.
  - 시간 `30px/800 letter-spacing -0.9 tabular-nums`, 종료 시각은 `ink3` 600.
  - 프로그램명 `16px/660`, 태그 행 gap 6(교시, 강습/안전근무, 대직이면 `대직 · {원담당} 강사 대신` amber).
  - 버튼: `출근하기`(blue) / `인수인계 메모`(ink2).
- **센터 도착 알림 카드** — GeoCard, 아래 Interactions 참고.
- **월 급여 카드**: 라벨 `실수령액 예상 (3.3% 공제 후)`, 금액 `30px/800 letter-spacing -1`, 정규/대직 2분할 스탯 박스(`bg`, radius 12), 주간 진행바(기준 14시간 대비, 초과 시 `amber`), 하단 구분선 위 단가 요약.
- **액션 카드 2개**: `1fr 1fr` 그리드, 아이콘 23px → 라벨 `15.5px/710` → 부제 `13px ink3`.

#### 3. 대직 (지원하기 / 내 요청)
- **Purpose**: 모집 중인 대직을 찾아 지원하고, 내가 올린 요청을 관리.
- **Layout**: 제목 → 서브탭 2개(밑줄 2.5px) → 필터 칩 가로 스크롤 → 카드 목록.
- **필터 칩 6개**: 전체 / 지원 가능 / 강습 / 안전근무 / 어린이 / 성인. 높이 38, radius 19, 활성 = `ink` 배경 + 흰 글자.
- **"지원 가능한 것만" 토글**: 체크박스형, 활성 시 텍스트가 `blue`.
- **공고 카드**: 4개 정보만 — D-day 태그 · 시간 · 프로그램 · 수당. 지원 전에 **예상 수당과 실수령을 같이** 보여줍니다. 원 담당·대상·난이도·메모는 상세 시트로 내렸습니다.
- **마감된 공고**: `opacity 0.56`, 태그 `마감 · {확정자}`.
- **시간 충돌**: 카드에 `일정 겹침` amber 태그 + 지원 버튼 비활성.
- **상세 시트**: 프로그램명 `23px/800`, 5행 정보표(날짜·시간·대상·예상 수당·요청 사유), 인수인계 메모 블록(`bg`, radius 14), 안내 배너 3종(본인 요청 차단 / 시간 충돌 / 지원 확정 안내). 하단 버튼: `닫기`(92px 고정) + `{금액} 대직 지원`. D-2 이내면 `red`, 그 외 `primary`.

#### 4. 대직 요청 (전체 화면 3단계)
- **Purpose**: 근무를 비우는 요청. 원본은 필드 12개가 한 모달에 몰려 있었습니다.
- **Steps**: `어떤 근무를 비울까요?` → `사유와 전달사항` → `이대로 요청할까요?` → 완료 화면.
- **1단계**: 예정된 정규 근무를 선택 카드로 나열(체크 원 24px). 다중 선택 가능. 하단에 점선 테두리 `목록에 없는 시간 직접 입력` 버튼 → 날짜·시작·종료·프로그램 입력. 선택된 근무가 있으면 직접 입력은 **사용되지 않는다는 경고**를 amber 박스로 표시.
- **시간·대상·난이도는 선택한 근무에서 자동으로 가져옵니다.** 강사가 다시 입력하지 않습니다.
- **2단계**: 사유 칩 5개(병원 진료 / 자격 연수 / 개인 사정 / 경조사 / 대회·행사 차출, 높이 44 radius 22), 메모 textarea(min-height 116, `bg`), 빠른 문구 3개(`+ 진도표는 강사실 책상 위에 있어요` 형태로 append).
- **3단계**: 요약 카드 + 예상 동작 안내 3줄(전원 알림 / 선착순 확정 / D-2 관리자 배정).
- **Validation**: 1단계 `chosenShifts.length > 0`, 2단계 `reason != null`일 때만 `다음` 활성. 비활성 시 `opacity 0.38`. **⚠️ 접근성 개선 필요**: 현재 비활성 상태가 `opacity`로만 표현되어 `disabled` 속성이 없습니다. 구현 시 `disabled` + `aria-disabled="true"`를 함께 넣어 키보드 포커스에서 제외하세요.

#### 5. 일정 (월간 / 주간)
- **Purpose**: 한 달 또는 한 주의 근무를 한눈에.
- **월간**: 7열 그리드, 날짜 셀 46px 높이, 선택일은 `ink` 배경 + 흰 글자, 오늘은 `blueSoft` 배경. 하단 점 4.5px: 정규 `blue` / 대직 `amber` / 요청중 `ink3`.

- **선택일 상세**: 카드 좌측 4px 컬러 바(정규 `blue` / 대직 `amber` / 요청중 `ink3`), 시간 `17px/760`, 프로그램, `강습 3교시 · 어린이 중급` 형태의 메타.

#### 6. 내 정보
- **Purpose**: 프로필·자격증·급여·설정·데모 계정 전환.
- **Layout**: 아바타 58px(radius 29, `blueSoft`) + 이름 21px/800 + 직급 태그 → `정규 근무` 카드(주간 배정/월 누적 스탯, 자격증 태그, 프로그램 태그) → 급여 명세 카드(정산 상태 태그 + 항목별 4~5행 + 실수령액 24px/800) → 설정 리스트(높이 56~58px 행) → 적용 단가 박스 → 데모 계정 전환.

#### 7. 관제 (대시보드)

- 3분류 탭: `긴급` / `모집 중` / `확정`. 카운트는 `긴급`이 0보다 크면 빨간색.

#### 9. 근무표
- **주간 그리드**: 좌측 강사명 열 52px + 7일. 셀 최소 높이 46, 근무 2건 이상이면 각 21px로 분할. 대직 확정은 `oklch(0.94 0.055 72)`, 요청중은 흰 배경 + 점선 보더.
- **월간 보기**: 강사 카드마다 7칸 미니 바(높이 32, 교시 수 표시).
- **이번 주 요약**: 정규 강습 교시 / 안전근무 시간 / 확정 대직 / 미구인(빨간색).
- **대직 확인서** (전체 화면 시트): 확정된 대직의 교시별 프로그램을 자동 기입. 4열 표(`교시 38px / 시간 88px / 프로그램 1fr / 편집 30px`), 행마다 연필 아이콘으로 프로그램명 수기 정정(모달 + 빠른 선택 5개). CSV 내보내기 가능.
- **강사 상세 시트**: 프로필 → 스탯 3개 → **경력별 적용 단가 3칸**(현재 적용 단가에 `ink` 테두리 하이라이트) → 정규 근무 + 주간 진행바 → 자격증 → 프로그램 → 이번 주 배정.

#### 10. 급여
- **총액 카드**: 실지급 총액 `31px/800`, 세전/원천징수 2분할, 정산 상태 태그(`정산 대기 · N명` amber / `10월 정산 확정` green).
- **강사별 정산 표**: 4열 그리드 `1.3fr 0.7fr 1fr 26px`. 행 클릭 → 조정 모달(금액 + 사유 + 조정 후 실수령 미리보기).
- **정산 확정**: 버튼 한 번으로 잠금. 확정 후에는 행이 `Lock` 아이콘으로 바뀌고 조정 진입이 막힙니다.
- **설정 탭**: 지급 단가 5개 입력(강습 1/2/3년차, 안전 평일/주말), 주간 시간 안내 기준, 신규 대직 알림 토글, **도착 인증 반경(m)**. 저장하면 급여·명세·정산표가 즉시 재계산됩니다.

## Interactions & Behavior

### 대직 확정 로직 (핵심 비즈니스 규칙)

`tm2AssignSubstitute(schedules, req, subUid, subName)` 하나로 지원·직권 배정이 모두 처리됩니다.

1. 원 담당의 해당 근무 → `status: 'sub_out'` (급여 계산에서 제외)
2. 대체 강사에게 새 근무 레코드 생성 → `status: 'sub_assigned'`, `subFor: 원담당명`
3. 이미 배정된 경우 중복 생성하지 않음(`already` 가드)

**반드시 지킬 것**
- **본인 요청에는 지원 불가** — 버튼 대신 안내 배너.
- **시간 충돌 차단** — `start_a < end_b && start_b < end_a`로 판정. 시각을 분(minute)으로 변환해 비교.
- **지원 즉시 자동 확정**(선착순). 관리자 승인 단계는 "D-2까지 지원자가 없을 때"만 개입합니다.
- **취소 시 원상 복구** — 요청 취소는 원 담당 근무를 `regular`로, 대체 강사 근무를 `canceled`로 되돌립니다.

### 급여 계산 (그대로 구현하세요)

```
강습 1교시 = 경력단가        // 1년차 26,000 / 2년차 27,000 / 3년차 이상 28,000
안전 1시간 = 요일별 단가      // 평일 17,000 / 토·일 18,000
세전 총액 = 정규강습 + 정규안전 + 대직강습 + 대직안전 + 관리자조정
원천징수   = round(세전 × 0.033)
실수령     = 세전 − 원천징수
```

- 경력 판정: `exp` 문자열에서 정수를 파싱해 1 / 2 / 3 이상으로 분류. 파싱 실패나 0 이하는 **1년차로 폴백**.
- `sub_out` 근무는 급여에서 제외, `sub_assigned`/`sub_done`은 **대직 항목으로 분리 집계**(강사가 "정규냐 대직이냐"를 구분해 볼 수 있어야 함).
- 주말 안전근무 시간은 별도 카운트(`regGtW`, `subGtW`)해서 명세에 `3시간 × 18,000 (주말)`처럼 근거를 보여줍니다.
- 관리자 조정은 금액 + **사유**를 함께 저장. 확정 후 잠금.
- 단가는 하드코딩하지 말고 **설정에서 주입**되게 하세요. 프로토타입은 모듈 전역(`TM2_RATES`)에 최신 설정을 반영해 계산 함수가 참조합니다.

### GPS 출근 반경 알림

- `watchPosition({ enableHighAccuracy: true, maximumAge: 4000, timeout: 15000 })`으로 좌표를 계속 수신.
- 센터 좌표까지 **haversine** 거리 계산 → `dist <= radius`(기본 200m)면 도착.
- **진입 1회만 발화**: `inside` 상태를 ref에 들고 있다가 상승 엣지에서만 콜백. **나갈 때 `radius × 1.3` 이상 벗어나야 재무장** — GPS 오차로 경계에서 흔들리면 알림이 반복 발화하기 때문입니다. 이 히스테리시스는 반드시 유지하세요.
- 도착 시: 도착 시트 + `new Notification()` (권한이 `granted`일 때만).
- 이미 출근 기록이 있으면 시트를 띄우지 않고 토스트만.
- 권한은 **토글을 켜는 클릭 안에서만** 요청합니다. 차단·미지원·타임아웃을 각각 구분해 카드에 이유를 그대로 표시하고, 어느 경우에도 **수동 출근은 계속 가능**해야 합니다.
- 시트가 열린 뒤 거리가 계속 변하지 않도록 **발화 시점 거리를 고정**합니다.

#### 웹의 한계 — 구현 시 반드시 확인
- 탭이 열려 있을 때만 감지됩니다(`GeoCard` 하단에 이 문구를 노출 중).
- 브라우저가 백그라운드에서 `watchPosition`을 중단하면 **출근 시간에 알림이 오지 않습니다.** 이 기능이 제품의 핵심이라면 네이티브 지오펜싱(iOS `CLCircularRegion` / Android `GeofencingClient`)으로 구현하고, 웹 프로토타입은 UX 레퍼런스로만 쓰세요.
- 알림 권한·위치 권한은 **거부 후 재요청이 불가**한 경우가 많습니다. 거부 상태를 저장하고 설정 화면으로 안내하는 경로를 만드세요.

### 데모 시뮬레이션 (프로토타입 전용 — 프로덕션에서 제거)
위치가 막힌 환경에서 흐름을 확인하기 위한 장치입니다.
- `데모로 확인` → 900m에서 시작, **460ms마다 75m씩 감소**. 200m 아래로 내려가면 실제와 동일한 도착 시트·알림이 발화.
- 프로토타입에는 이 경로가 남아 있습니다. 실제 앱에서는 `geo.source === 'sim'` 분기와 함께 제거하세요.

### 시트(바텀시트) 동작
- 일반 시트: 배경 `rgba(12,18,26,.44)`, 패널 최대 높이 88%, radius `26px 26px 0 0`, 핸들 38×5px.
- 전체 시트: `top: 54px`부터 화면을 덮음.
- 트랜지션: `transform .34s cubic-bezier(.22,.85,.25,1)`, 열림 `translateY(0)` / 닫힘 `translateY(105%)`. 배경은 `opacity .24s`.
- **닫힌 시트도 DOM에 남아 있습니다.** `pointer-events: none` + `translateY(105%)`로 가려질 뿐입니다. 접근성·테스트 자동화를 위해 닫힌 시트는 `aria-hidden="true"`를 주거나 조건부 렌더링으로 바꾸는 것을 권합니다. (실제로 이 때문에 자동 검증에서 "엉뚱한 시트가 열린 것처럼" 보이는 오독이 발생했습니다.)

### 토스트

## State Management

### 필요한 상태

```
schedules[]      // 개별 근무 레코드 (날짜별로 materialize)
requests[]       // 대직 요청
attendance{}     // uid_date 키 → { in, out, method }
adjust{}         // uid_month 키 → { amount, reason }
settled{}        // month → boolean
settings{}       // 단가 5종 + threshold + alerts + radius + geo
onboarded        // boolean
me               // 현재 로그인 강사 id
```

### 근무 레코드 형태
```js
{ id, uid, date: 'YYYY-MM-DD', start: 'HH:MM', end: 'HH:MM',
  program, type: 'lesson' | 'lifeguard', target, level, count,
  status: 'regular' | 'done' | 'sub_requested' | 'sub_assigned' | 'sub_done' | 'sub_out' | 'canceled',
  reqId?, subFor?, manual? }
```

### 상태 전이
| 트리거 | 변화 |
|---|---|
| 대직 요청 생성 | `requests`에 `recruiting` 추가, 선택한 근무들 → `sub_requested` + `reqId` |
| 지원 / 직권 배정 | 요청 → `confirmed`, 원 근무 → `sub_out`, 대체 강사에 `sub_assigned` 근무 생성 |
| 요청 취소 | 요청 → `canceled`, 원 근무 → `regular`, 대체 근무 → `canceled` |
| GPS 진입 | `attendance`에 `{ in, out: '', method: 'gps' }` |
| 퇴근 | 같은 레코드의 `out` 갱신 |
| 정산 확정 | `settled[month] = true` → 조정 잠금 |

### ⚠️ 파생 상태 주의
**주간 시간, 주간 배정 시간, 월 누적 시간은 저장하지 말고 매번 `schedules`에서 계산하세요.** 프로토타입은 세 곳에서 각기 다른 필터로 계산하고 있습니다(`tm2WeeklyHours`, 홈의 `week`, `IMe`의 누적). 저장된 카운터를 두면 대직 확정·취소 시 반드시 어긋납니다. 하나의 헬퍼로 통일하는 것을 권합니다.

### 데이터 페칭
원본은 Firebase였습니다. 구현 시 최소한 필요한 실시간 구독은 **`requests`(모집 중 목록)** 하나이고, 나머지는 화면 진입 시 조회로 충분합니다. 70명 / 월 1,000슬롯 규모에서 전체 `schedules` 실시간 구독은 과합니다.

### 영속성
프로토타입은 `localStorage`를 씁니다(`tm3_state`, `tm3_me`, `tm_role`, `tm_tab`). 탭·역할을 저장하는 이유는 **새로고침 후에도 보던 화면으로 돌아오게** 하기 위해서입니다. 구현 시에도 "마지막 탭 유지"는 유지하세요.

## 구현 우선순위 (권장)

1. **`store.jsx`의 계산 로직** — 급여·대직 확정·주간 집계. 여기가 틀리면 화면이 아무리 예뻐도 신뢰를 잃습니다.
2. **정규시간표 자동 채움 + [맞아요] 확인** — 이번 릴리스의 실제 목표. 위 "미설계" 섹션의 결정 사항을 따르세요.
3. **강사 홈 + 대직 흐름** — 가장 자주 쓰는 경로.
4. **GPS 반경 알림** — 네이티브 지오펜싱 여부를 먼저 결정한 뒤 착수하세요. 웹으로는 백그라운드 알림이 불가능합니다.
5. **관리자 화면** — 관제 → 승인 → 급여 순. 관리자 수가 1명이라면 화면보다 **임포트 도구가 먼저**입니다.
